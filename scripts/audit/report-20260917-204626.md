### 1. Mid-attempt answers do not survive a refresh (no save path; client resets all answers on reopen)

- **Severity:** `blocker`
- **Category:** `broken-flow`
- **Group:** student / student-quizzes
- **Location:** components/student-quiz-attempts.tsx:121,139 / app/api/student/quiz-attempts/
- **Evidence:** Getting /api/student/quiz-attempts as demo.student1@school.edu returned the demo quiz as canStart with 4 questions; listing app/api/student/quiz-attempts shows only route.ts (list/start), [attemptId]/route.ts (GET), [attemptId]/submit/route.ts and practice/route.ts — there is no save/autosave endpoint, and the rendered attempt UI (components/student-quiz-attempts.tsx) sets every answer to null in startAttempt() and openAttempt() ('setAnswers(Object.fromEntries(body.attempt.questions.map((q) => [q.id, null])))') and clears textAnswers to {}.
- **Why it matters:** A student who answers three of four questions and refreshes, or reopens the in-progress attempt, sees an entirely blank quiz and loses all typed/selections with no warning, because nothing is ever written until Submit.

### 2. No authoring surface in the teacher workspace exposes a draft/publish control

- **Severity:** `major`
- **Category:** `missing-write-path`
- **Group:** teacher / teacher-authoring
- **Location:** /teacher/assignments (and /teacher/quiz-generation, /teacher/rubrics, /teacher/code-tasks; app/(dashboard)/teacher/assignments/page.tsx)
- **Evidence:** GET /teacher/assignments, /teacher/quiz-generation, /teacher/rubrics and /teacher/code-tasks as demo.teacher@school.edu each returned 200 OK with the rendered teacher shell, so the pages load; list_dir of app/(dashboard)/teacher shows each of those four surfaces is a single page.tsx with no [id] detail route or sub-components. grep -r 'Publish|Unpublish|Save draft|Draft' app/(dashboard)/teacher returns only app/(dashboard)/teacher/offerings/page.tsx:24,25,54, and there the match is resultsPublishedAt / 'Publishing results' — publishing a cohort's marks and starting a retention clock, a different concept from assessing an authored item. No sentence-case draft/publish label reaches any of the four authoring surfaces.
- **Why it matters:** A teacher authoring an assignment, quiz, rubric or code task has no way to mark it as finished or withheld, and no visible state saying which items are live, so an unfinished item is indistinguishable from a published one and the draft-to-published lifecycle this slice is meant to demonstrate cannot be exercised at all.

### 3. Submissions queue's only per-row action, "Open", links every row to the same /teacher/assignments page and loses which submission was clicked

- **Severity:** `major`
- **Category:** `dead-control`
- **Group:** teacher / teacher-grading
- **Location:** /teacher/submissions, components/teacher-submissions-table.tsx:261
- **Evidence:** GET /teacher/submissions as demo.teacher@school.edu returned 200 with real rows (GET /api/teacher/reviews returns 3 PENDING items for the same teacher). The row action in components/teacher-submissions-table.tsx:261-268 is <Link href="/teacher/assignments" ...> — a literal path with no row.id, row.assessmentId or student interpolated — while its aria-label is `Open ${row.studentName}'s submission for ${row.assessmentTitle} in assignments`. The page copy and SectionCard description confirm this queue is read-only and that grading must happen on /teacher/assignments.
- **Why it matters:** A teacher clicking "Open" on a specific student's submission is dropped on the generic assignments list with no indication which submission they meant, so the queue's one action cannot be used to reach the grading editor for the row that was clicked; screen-reader users are told a specific submission is being opened when it is not.

### 5. "Round progress ... Evaluations submitted 3 of 3" counts the student's own ratings while the results gate counts teammates' ratings, so the round looks complete and still shows no results

- **Severity:** `minor`
- **Category:** `inconsistency`
- **Group:** student / student-collaboration
- **Location:** /student/peer-evaluation (components/student-peer-evaluation.tsx:315-333, 427-436)
- **Evidence:** GET /student/peer-evaluation as demo.student1@school.edu returned 200 and rendered "Round progress — Team Alpha" / "DEMO-MATH-101 · Algebra Foundations" with the progress line "Evaluations submitted 3 of 3"; the same session's GET /api/student/peer-evaluation returns submittedEvaluations:3, expectedEvaluations:3 and received:{withheld:true, ratingCount:2, minRatersRequired:3}, which the component renders as the withheld card "Ratings received 2 of 3 needed", directly under the copy "Results appear only after at least 3 teammates have submitted".
